## Current state of the repo (read this before trusting the docs' commands)

The docs describe the target architecture. The code is early:

- Built so far: `src/shared/lib/supabase/{browser,server}.ts`, `src/shared/types/{database.types,result,errors}.ts`, `src/shared/lib/questionEngine.ts` (zero-drop question builder: cloze, key–value recall, true/false, recognition, fallbacks) + `notePatterns.ts` (implicit subject, pairs, cloze targets) + `trapEngine.ts` (true/false mutations; + `trapDictionary.ts`, `shared/utils/seededRandom.ts`), all pure, `src/shared/lib/treeSkins.ts` (species catalog: ids, forms, colors, `GOLDEN_BLOOM_PERCENT`), `src/features/decks` (`getDecks`, `getDeckBySlug`, `createDeck`, `createMindmapNode`, `createKnowledgeItem`, `getDeckEditor`, `CreateDeckForm`, `DeckEditor`, `server.ts`), `src/features/garden` (Farm World at `/`: a 16 × 16 isometric grid `FarmIsometricGrid` with a 🏪 Shop `FarmShopModal` and placement mode; owns `garden_placements` with actions `getFarmPlacements` / `placeFarmItem` / `removeFarmPlacement`; coin buffs `lib/farmBuffs.ts`; `GardenGrid` at `/?view=grid`, `TreeCard`, `TreeStageSvg` with 6 species × 5 stages, `getTreeStage`). Coins are the only currency (no gems), `src/shared/hooks/useDragPan.ts`, `src/features/drill` (`getDrillSession`, `checkDrillAnswer`, `DrillOverlay`), `src/features/auth` (magic link, `LoginDialog`, `ProfileButton`), `src/features/progress` (`submitDrillResult`, `getProgressByDecks`, `getGardenStats`, `masteryRules`), `src/features/mindmap` (`RootMap` mindmap canvas, pure `layoutMindmap`, mastery helpers), `src/shared/hooks/useCamera.ts` + `src/shared/lib/camera.ts` (drag/pinch/zoom camera for farm + mindmap), `src/features/user-profile` (UI only: `GardenerCard`, `GardenStatsGrid`, `PlantedTreeList`), `src/features/tournament` (Mind Tournament: `submitTournamentAnswer`, `getTournamentBoards`, `TournamentBoard`; rounds via drill `getTournamentSession` at `/deck/[slug]/tournament`; host switch decks `setTournamentOpen`), `src/shared/components/SignInPrompt.tsx`, `src/proxy.ts` (session refresh), pages `/`, `/profile`, `/deck/new`, `/deck/[slug]`, `/deck/[slug]/drill` (`?nodeId=` for one branch), route `/auth/callback`.
- Next.js is **16.3.6** (React 19.2). Check `node_modules/next/dist/docs/` before using any Next API (see the Next.js block above).
- Installed: Supabase (`@supabase/ssr`, `@supabase/supabase-js`), `zod`, `server-only`, `lucide-react`, `canvas-confetti`, Tailwind v4, shadcn/ui.
- shadcn/ui: `components.json` aliases point to `@/shared/components/ui` and `@/shared/utils/cn`. Components import `cn` from the official `cn` npm package, so `npx shadcn add <name>` works as is.
- `database.types.ts` is **hand-written** from DATABASE.md. Replace it with `supabase gen types` output once migrations exist.
- Vitest 5 is set up (`vitest.config.mts`, `@` alias). Tests live in `src/**/__tests__/*.test.ts`; `npm test` runs once, `npm run test:watch` watches. `server-only` is stubbed in Vitest (`src/test/server-only.ts`).
- `src/shared/lib/supabase/admin.ts` (service role) is used only by `decks/services/answers.ts` (read `correct_stmt` / `trap_rules`) `progress/services/streak.ts` (write `practice_days`, `users` streak counters) and `progress/services/coins.ts` (call `award_mastery_coin`, the only writer of `users.coins`) and `tournament/services/answers.ts` (call `record_tournament_answer`, the only writer of the tournament tables); a guard test enforces this. Set `SUPABASE_SERVICE_ROLE_KEY` in `.env.local` (never `NEXT_PUBLIC_`). Without it, answer reads fall back to the user client, which stops working once `supabase/migrations/20260928000100_hide_knowledge_answers.sql` is applied.
- `supabase/migrations/` runs in this order on a fresh database: `20260928000000_initial_schema.sql` (baseline tables, trigger, RLS) → `20260928000100_hide_knowledge_answers.sql` → `20260928000200_practice_days.sql` → `20260928000300_user_coins.sql` → `20260928000400_mastery_scale_5.sql` → `20260928000500_seed_economy.sql` → `20260928000600_profiles_and_sharing.sql` → `20260928000700_clone_deck.sql` → `20260928000800_tree_visits.sql` → `20260928000900_mind_tournament.sql` → `20260928001000_display_names.sql` → `20260930000000_farm_grid.sql` → `20261001000000_ten_tree_species.sql` → `20261002000000_move_garden_placement.sql` (details: DATABASE.md "Migration Rules"; on the hosted project run file 5 first, then deploy the code, then file 4, then file 6 right with the deploy; files 7–12 any time after that, in order; file 13 only after the ten-species code is deployed; file 14 any time after 12). Economy: 300 🪙 start, 100 🪙 per tree (`shared/lib/economy.ts`); decks are created only through the `plant_deck()` or `clone_deck()` RPCs (cloning a shared tree costs `cloneCost(n)` = min(100 + statements, 150) 🪙); the Coin Shop's free top-up works only outside production. Gardens are isolated: `getDecks` returns only the session user's own decks; other gardeners' shared (`is_public`) trees are found by link: opening one (`/deck/[slug]`, signed in, not yours) records a visit (`TreeVisitTracker` → `recordTreeVisit` → `record_tree_visit()` RPC, table `tree_visits`), and the farm's left **Visited Gardens** drawer (`getVisitedGardens`, garden `VisitedGardensDrawer`) lists those trees by gardener; `getNeighborGarden` shows one gardener's shared island (read-only visitor mode, `/?visit=<id>`, which records no visits). There is no public directory of shared trees (Community Gardens and `getCommunityDecks` were removed). Visitor mode is **strict**: visitors read every root and statement (`getDeckReader`) but can't edit or practise; `getDrillSession` / `checkDrillAnswer` / `submitDrillResult` are owner-only (`FORBIDDEN_VISITOR_PRACTICE`, `shared/lib/visitor.ts` `canPractice`), so to practise they clone the tree (`cloneDeck`, progress not copied). The one exception is a **Mind Tournament** the owner hosts on a public tree (`decks.is_tournament_open`): signed-in visitors drill it with an isolated score (`deck_tournament_*` tables, never `user_progress` / streaks / coins), ranked on the 📜 Hall of Fame (graduates by fewest practice days) and 🌱 Active Learners boards (`shared/lib/visitor.ts` `tournamentAccess`). New trees are private by default. Mastery is 0–5 (`shared/lib/mastery.ts`, `MAX_MASTERY`); 5/5 items rest from normal drill rounds unless `?review=1`. The existing hosted project's base schema was built in the dashboard and already has files 2–3: never run the baseline there; apply new migrations in the SQL Editor.
- **Not set up yet**: the Supabase CLI project (`supabase/config.toml`). If a task needs one of these, set it up first or ask the user.
- Commands that work today: `npm run dev`, `npm run build`, `npm run lint`, `npx tsc --noEmit`, `npm test`. Run `npx next typegen` before `tsc` after adding a route, so `PageProps<...>` knows it.

- The repo path contains non-ASCII characters (`Tài liệu`). Quote paths in shell commands.
- When you add a feature, also create `src/features/<feature>/context.md` (owned tables, exports, dependencies) as the docs require.
