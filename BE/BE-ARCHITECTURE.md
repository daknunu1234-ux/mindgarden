# Backend Architecture

> **Read when**: adding a feature, moving code between folders, or touching the drill / trap engine flow.
> **Related**: [PROJECT-RULES.md](./PROJECT-RULES.md) · [../API_SPEC.md](../API_SPEC.md) · [../DATABASE.md](../DATABASE.md) · [../frontend/ARCHITECTURE.md](../frontend/ARCHITECTURE.md)

## 1. Tech Stack

| Technology | Purpose |
|------------|---------|
| Next.js App Router | Server Actions (primary API), Route Handlers (`/api/*`, `/auth/callback`) |
| TypeScript (strict) | Typed actions, services, DTOs |
| Zod | Validate every incoming payload (`features/*/dto`) |
| `@supabase/ssr` | Cookie-based server client (`shared/lib/supabase/server.ts`) |
| `@supabase/supabase-js` | Typed `Database` client, admin client for streak writes |
| Supabase PostgreSQL + RLS | Data + final security guard (see DATABASE.md) |
| Vitest | Unit tests for pure logic (trap engine, mastery rules) |

---

## 2. System Overview

- **Style**: Monolith. Next.js App Router is the whole backend; Supabase provides auth, the database and RLS
- **Trap Engine**: deterministic, pure TypeScript utility run on the server; no DB, no network, no LaTeX

```
Browser (React 19)
  │
  ├──► Server Components ─┐
  ├──► Server Actions ────┼──► features/*/services ──┬──► Supabase Auth
  └──► Route Handlers ────┘                          └──► PostgreSQL + RLS
                │
                └──► shared/lib/trapEngine.ts (pure: no DB, no network)
```

## 4. Feature Anatomy

One folder per feature holds both its server and UI code. Only the folders a feature needs are created.

```
features/[feature]/
├── actions/      # SERVER · 'use server' entry points: validate → auth → service → ActionResult
├── services/     # SERVER · Supabase queries (import 'server-only'); the only layer touching the DB
├── dto/          # SHARED · Zod schemas (DrillSubmissionDto, CreateDeckDto)
├── lib/          # SHARED · Pure helpers (progress/lib/masteryRules.ts)
├── types/        # SHARED · Domain types + UI view models
├── components/   # CLIENT · UI (see frontend/PROJECT-RULES.md)
├── hooks/        # CLIENT · UI state, calls actions
├── __tests__/    # Vitest
├── index.ts      # Public, client-safe: actions, components, hooks, types
├── server.ts     # Public, server-only: services for other features' server code
└── context.md    # Owned tables, exports, allowed dependencies
```

- `index.ts` never re-exports `services/` (it would pull `server-only` code into the client bundle)

## 5. Feature Boundaries (server side)

| Feature | Owns tables | Actions | May import |
|---------|-------------|---------|------------|
| `auth` | `roles`, `users` (except streak columns) | none (OAuth via `/auth/callback`) | `shared` |
| `decks` | `decks`, `mindmap_nodes`, `knowledge_items` | `getDecks`, `getDeckBySlug`, `createDeck` | `shared` |
| `progress` | `user_progress`, `users.streak_count`, `users.last_active_at` | `submitDrillResult`, `getProgressByDecks` | `shared`, `decks/server` |
| `drill` | none (orchestrator) | `getDrillQuestion` | `shared`, `decks/server`, `progress/server` |
| `garden`, `mindmap` | none (UI only) | none | `shared` |

- **Direction**: `drill` → `progress/server` → `decks/server`; `drill` → `decks/server`; every feature → `shared`. Never the reverse, no cycles

## 6. Request Flow

```
Client (form / hook)
  │  submitDrillResult({ itemId, seed, tag })
  ▼
Server Action ('use server')
  │  1. DrillSubmissionDto.safeParse(input) ── fail ──► { success: false, error: VALIDATION_FAILED }
  │  2. supabase.auth.getUser()            ── none ──► { success: false, error: AUTH_UNAUTHORIZED }
  ▼
Feature Service: recordDrillResult(supabase, user.id, dto)
  │  select / upsert (user JWT attached)
  ▼
PostgreSQL (RLS enforced) ── denied ──► empty rows / policy error
  │  rows
  ▼
ActionResult<T> ──► Client receives { success, data, meta } or { success, error }
```

| Step | Responsibility | Failure code |
|------|----------------|--------------|
| Zod validation | Shape, lengths, UUIDs, plain-text check | `VALIDATION_FAILED` |
| Auth check | Resolve user from cookie session | `AUTH_UNAUTHORIZED` |
| Service query | Business logic + Supabase call | `*_NOT_FOUND`, `INTERNAL_ERROR` (full list: API_SPEC.md §5) |
| RLS | Final safety net at DB level | Empty rows or a policy error |

## 7. Plain-Text Trap Engine

**Signature** (`shared/lib/trapEngine.ts`):
```typescript
export type TrapRules = { swaps?: { from: string; to: string }[]; negate?: boolean }
export type DrillChoice = { tag: 'A' | 'B' | 'C'; text: string }
export type TrapResult =
  | { ok: true; choices: DrillChoice[]; correctTag: DrillChoice['tag'] }
  | { ok: false; reason: 'INSUFFICIENT_MUTATIONS' }
export function generateTraps(correctStmt: string, rules: TrapRules, seed: string): TrapResult
```

```
correct_stmt + trap_rules + seed
  ▼
1. trap_rules.swaps        (configured keywords)
  ▼
2. Opposite pairs          (tăng ↔ giảm, lớn hơn ↔ nhỏ hơn)
  ▼
3. Negations (if negate)   (is ↔ is not, là ↔ không phải là)
  ▼
4. Operators               (* ↔ /, + ↔ -)
  ▼
Candidate pool             (dedupe, drop == original)
  ├── 0 candidates ──► { ok: false, reason: 'INSUFFICIENT_MUTATIONS' }
  ├── 1 candidate  ──► 2 choices: seeded shuffle, tag A / B ──► { choices, correctTag }
  ▼ ≥ 2
Seeded pick of 2 distractors ──► seeded shuffle, tag A / B / C ──► { choices, correctTag }
```

| Source | Match rule | Example |
|--------|------------|---------|
| `trap_rules.swaps` | Case-insensitive whole word/phrase | `ATP` → `DNA` |
| Opposite pairs | Both directions, longest phrase first (`trapDictionary.ts`: tăng/giảm, trước/sau, trong/ngoài, tạo ra/tiêu thụ, inhale/exhale, produce/consume…) | `Nhiệt độ tăng` → `Nhiệt độ giảm` |
| Negations | Only when `trap_rules.negate` is true; both directions, longest first | `Ty thể là bào quan` → `Ty thể không phải là bào quan` |
| Operators | Only between operands (`3 * 4`, `a+b`); tight `-` and `/` need digits on both sides, so hyphens in words and units (`km/h`) are skipped | `F = m * a` → `F = m / a` |

- **One mutation per distractor**: each trap differs from the original in exactly one place
- **Unicode-safe boundaries**: `(?<!\p{L})…(?!\p{L})` with the `u` flag; `\b` breaks on Vietnamese diacritics
- **Deterministic**: `seed = hash(itemId + sessionId)`, computed in `getDrillQuestion`; the engine only uses `seededRandom(seed)`
- **Grading**: the client receives `choices` + `seed` (never `correctTag`); `submitDrillResult` re-runs the engine with the same seed
- **Choice count**: 3 choices when ≥ 2 traps exist, 2 (true vs. one trap) when only 1 does. A submitted `C` on a 2-choice question is simply wrong
- **Insufficient mutations** (0 traps): drill sessions skip the item; the deck editor marks it 💧 and suggests flippable words (authors never edit trap rules)

## 8. Shared vs Feature Scope

| Shared (`src/shared/`) | Feature (`src/features/*`) |
|------------------------|----------------------------|
| Supabase client factories (`server`, `browser`, `admin`) | Query services (`getDeckTree`, `recordDrillResult`) |
| `trapEngine.ts`, `trapDictionary.ts`, `seededRandom` | Action validators (`CreateDeckDto`, `DrillSubmissionDto`) |
| `ActionResult<T>`, `ErrorCode`, `database.types.ts` | Domain entities (`DeckTree`, `MasteryLevel`), `masteryRules.ts` |

**Rule of thumb**: code goes to `shared/` only if it has no feature knowledge and is used by 2+ features (or is infrastructure).

## 9. Key Design Decisions

| Decision | Why |
|----------|-----|
| Server Actions over REST | Type-safe calls, no API layer to maintain for a solo dev |
| One folder per feature (server + UI) | One place per domain; `index.ts` / `server.ts` keep the bundle split safe |
| RLS as the final guard | A bug in a service can't leak private decks |
| Seeded determinism | Reproducible drills, testable engine, grading without storing sessions |
| Streak via admin client | `users.streak_count` is not client-writable (DATABASE.md) |
