# mindmap

UI-only feature: "Inspect Roots", the deck's knowledge as a mindmap growing out of its tree.

## Owned tables
None. Never calls actions; pages pass the tree and item levels as props.

## Tree & roots chart (what the deck page shows)
The deck page's "Tree & roots" section is `RootChart`: the whole root hierarchy on a zoomable, pannable canvas. It replaced the older canvas `RootMap` there; `RootMap`, its layout (`layoutMindmap`), cards (`NodePill`, `StatementCard`) and scene helpers are still in the feature and exported, but no page mounts them.

| Export | Notes |

## Document → outline import (`lib/outlineParser/`, `components/OutlineImportDialog.tsx`)
A Word (.docx), PowerPoint (.pptx) or PDF file → a three-level outline (1 root, 2 sub-root, 3 statement) imported into the open tree. **Zero upload, zero storage, zero AI**: the file is read in the browser's memory (`File.arrayBuffer`), never sent or stored; only the confirmed lines (level + text) go to the server. Limit 10 MB (`MAX_OUTLINE_FILE_BYTES`), at most 1000 lines (`MAX_OUTLINE_ITEMS`). Tests: `__tests__/outlineParser.test.ts`, `__tests__/outlinePdfReal.test.ts` (a real PDF through pdf.js).

| Export | Notes |
|--------|-------|
| `OutlineImportButton({ renderReview })` (`index.ts`) | Client. "📄 Import from a document" → dialog: pick or drop a file → "Reading…" → the file's format and name, notes on what was dropped or split, then `renderReview({ fileName, format, lines, back, close })`: the page renders decks' `OutlineStagingEditor` there (the Tree Workshop's own editor, edited in memory, imported on Done; the mindmap never calls actions). `lines` carry level + text only. While reviewing, the dialog widens (`size="xl"`) and only ✕ closes it: Esc belongs to the outline's fields and a click outside is ignored, so staged edits are never lost by accident. The parsers, jszip and pdf.js load only when a file is picked (dynamic import), not with the deck page |
| `lib/outlineParser/index.ts` `parseOutlineFile(file)` | → `{ format, lines: VisualTextLine[], items: StagedOutlineItem[], notes }`; throws `OutlineFileError` with a player-facing message (unsupported / .doc / .ppt, over 10 MB, damaged, password-protected or scanned PDF). `readDocx`, `readPptx` (jszip, in memory), `readPdf` (pdf.js **legacy** build: the default one needs `Uint8Array.prototype.toHex`, missing before 2025 browsers; its worker is bundled through `new Worker(new URL(…, import.meta.url))`, so nothing is fetched from a CDN) |
| `docx.ts` `linesFromDocx({ document, styles?, numbering? })` | Pure. Per paragraph: Heading 1–3 / Title by the style's **name** in styles.xml (localised ids like "u1" work) or an outline level; list level (`w:ilvl`) and the list's number format from numbering.xml (I, A, 1, 1.1, •; Word stores automatic numbers as formatting); `w:ind` indentation (720 twips = a level); bold (≥ 80 % of the text); largest `w:sz` |
| `pptx.ts` `linesFromPptx({ slides, slideHeightEmu? })`, `slideOrder` | Pure. Slides in presentation order (presentation.xml + rels). Title / ctrTitle placeholders are isolated header boxes (the slide's heading, read first); other paragraphs keep bullet level (`a:pPr lvl`), bold, size, `a:buAutoNum`, line breaks and fields; y position 0–100 %. Notes, tables and charts are not read |
| `pdf.ts` `linesFromPdf(pages)` | Pure, from pdf.js text items. Items on one baseline → a line (gaps → spaces); left edges used 2+ times → indent levels; wrapped lines merged into paragraphs (same indent and size, close below, previous line not ending a sentence, no new marker); running headers / footers (same text and height on half the pages, 3+) and page numbers dropped; a short larger line with space around it → isolated header block. Bold from font names (embedded fonts: "…-Bold…"; the 14 standard fonts give none) |
| `classify.ts` `classifyOutline(lines, fallbackTitle)`, `headingScore`, `splitLong`, `normalizeStaged` | Pure. Heading score per line: Word Heading 1/2/3 90/80/70; isolated header 70–79 (by size); Roman 62, capital 57, number 52, sub-number 47 (short lines; numbered sentences are statements); larger than body text 43–54; bold short unindented 30; a short non-sentence with indented lines under it 20 − 2/level. The highest score present → roots, the next → sub-roots, everything else → statements. Then: statements < 5 chars dropped, > 500 split at sentence ends, headings > 150 chars → statements, sub-roots only → lifted, lines before the first root → under a root named after the file, consecutive repeats skipped. Shorthand ("Term: explanation", "Term - …") is kept as written, so the drill's parser and context inheritance work on the imported statements |

## Rules
- Cards show the statement text (`content_nodes.content`) to everyone who can read it: the owner wrote it (or cloned it) and already sees it in the Tree Workshop; visitors read shared trees. "Statement n" is only the fallback for a missing or blank text (`statementLabel`). Answers still stay secret where it matters: drill questions never carry `correctTag`, and grading happens on the server
- Per-statement drilling doesn't exist: rounds start from a top-level root pill (or the inspector), never from a statement card
- Mighty Root = the node's own statements all at 5/5 (same rule as the profile stats)

## Scene
`hooks/scene.ts`: `sceneGeometry(layout, surface, sideMargin?)` gives a fixed-size world (soil 480px past the roots on each side), the ground line, the tree box on the trunk, and a `focus` box for the camera to fit. `rootStroke`, `conduitPath`, `groundPath` are pure helpers.
