# decks

Server feature for decks and their content: roots and statements in one hierarchy (`content_nodes`).

## Owned tables
`decks`, `content_nodes`, `tree_visits` (only this feature's services query them; `legacy_mindmap_nodes` / `legacy_knowledge_items` are the pre-migration tables, unused)

## Seed prices (supersedes the flat "100 🪙" wording in the rows below)
- A seed costs its species' price: `shared/lib/treeSkins.ts` `seedPrice(treeType)` = 100 🪙, or 180 🪙 for the surreal species (`crystal_flora`, `cosmic_nebula`, `chrono_willow`). The database charges it (`seed_price()`, migration `20261006000000_species_seed_prices.sql`); the client never sends a price
- `createDeck`: `INSUFFICIENT_COINS` = "You need <price> coins to buy a seed for this tree!". `CreateDeckForm` follows the species picked (Seed Cost plaque, Plant button, disabled while short)
- `cloneDeck` / `CloneTreeButton({ …, treeType })`: fee = `cloneCost(statements, seedPrice(treeType))` = seed price + min(statements, 50): 100–150, surreal 180–230
- `updateDeck` → `UpdatedDeck` = `Deck & { remainingCoins: number | null }`: changing to a pricier species costs `speciesUpgradeCost(from, to)` (80 🪙), charged by the `decks_charge_species_upgrade` trigger; short purse → `INSUFFICIENT_COINS`. `remainingCoins` = the purse after a paid change (the deck draft pushes it into `CoinsProvider`), null otherwise
- `TreeSpeciesPicker({ …, coins? })`: every card carries `shared/components/game` `SeedPricePill` (dimmed red + tooltip when `coins` is short). `compact` (Workshop): a "+N" badge on species that cost extra; `DeckEditor`'s `TreeSettingsBar` asks in place before paying
- Tests: `__tests__/seedPrices.test.ts`, `createDeck.test.ts`, `cloneDeck.test.ts`

## Content nodes (supersedes the rows below where they differ)
- **Schema** (migration `20261013000000_content_nodes.sql`, DATABASE.md): `content_nodes` = `id, deck_id, parent_id, content, node_type ('root' | 'statement'), trap_rules, sort_order, created_at`. Any node under any node; a top-level node is a root (`TOP_LEVEL_STATEMENT`); no cycles (`NODE_CYCLE`). Progress (`user_progress`, `deck_tournament_item_progress`; column still `knowledge_item_id`) points at statement nodes. `indent_content_node(node, 'in' | 'out')` = Tab / Shift+Tab in place
- **Types** (`types/index.ts`): `NodeType`, `ContentRow { id, parentId, type, content, depth }` (the outline, in display order), `DeckEditor { deckId, treeType, rows, nodes }` (`nodes` derived: roots with their statements, `EditorItem.parentId` = the parent statement, `depth` = statements above), `DeckTreeItem { id, prompt, parentId?, depth? }`
- **`lib/contentTree.ts`** (pure, the one source of the outline rules, tested in `__tests__/contentTree.test.ts`): `outlineRows` (stored nodes → rows: each node, then its children by `sort_order`, `created_at`, `id`), `toEditorNodes`, `toDeckTree` (a statement belongs to its nearest root), `branchCounts`, `branchEnd`, `insertIndex` / `insertRow`, `removeRow`, `editRow`, `moveRow` (last child of a root; never into its own branch), `indentRow(rows, id, 'in' | 'out')` (Tab: last child of the sibling above; Shift+Tab: right below the old parent, adopting the siblings below; the row order never changes), `toggleRow` (Alt), and for an unsaved line `ContentSlot { parentId, afterId, type }`, `indentSlot`, `toggleSlot`. Each returns the new rows or a reason string
- **Services** (`services/content.ts`): every node read and write (`loadOutline`, `loadDeckEditor`, `loadDeckReader`, `createNode` (sort_order: midpoint after `afterId`, else max + 1), `insertMindmapNode`, `insertKnowledgeItem(s)`, `editKnowledgeItem`, `renameMindmapNode`, `removeKnowledgeItem`, `removeRootBranch`, `removeMindmapNode`, `moveKnowledgeItem`, `toggleNodeType`, `indentNode`). Owner check first (`authoring.ts` `checkDeckOwner`), RLS as the final guard. `services/authoring.ts` keeps the deck-level writes (plant, clone, settings, tournament, uproot)
- **Actions**: `actions/contentNodes.ts` `createContentNode({ deckId, parentId, type, content, afterId? })` → `{ id, drillable }`, `toggleNodeType({ deckId, nodeId })` → `{ id, type, drillable }`, `indentContentNode({ deckId, nodeId, direction })` → `{ id, parentId, movedChildren }` (DTOs in `dto/ManageRootsDto.ts`). The older actions (`createMindmapNode`, `createKnowledgeItem(s)`, `updateMindmapNode`, `updateKnowledgeItem`, `moveKnowledgeItem`, `delete*`) keep their inputs and run on `content_nodes`. Tests: `__tests__/contentNodeActions.test.ts` (in-memory database `src/test/fakeContentDb.ts`), `indentContentNodeDb.test.ts` and `contentNodesMigration.test.ts` (PGlite)
- **Practice**: `services/drillItems.ts` reads `content_nodes` of the tree (one table, no join) and drills every `statement`; `nodeId` = its nearest root, `path` / `ancestry` = the roots above (+ a short parent statement, `lib/statements.ts` `parentContext`), siblings = statements with the same nearest root. `services/answers.ts` `readTrapRules(ids)` is the only reader of `trap_rules` (service role)
- **Workshop** (`components/ContentOutline.tsx`, inside `DeckEditor`): one flat outline of rows (depth guides, ▾ / ▸ collapse with `+N`), chips per top-level root, the `ShortcutPanel` in a right column. Keys (`lib/outline.ts` `rowKey` / `outlineKey`, `OUTLINE_SHORTCUTS`): **Enter** saves and opens a sibling of the same type right below (the only key that creates), **Shift+Enter** / Esc / blur save, **Tab** / **Shift+Tab** change the row's level in place (`indentRow`, or `indentSlot` on a new line), **Alt** (clean tap) / **Alt+Enter** flip root ↔ statement in place (`toggleRow` / `toggleSlot`), **Ctrl+Enter** opens the bulk importer. Hover tools: ＋📜 / ＋↳, ＋🌿, ✏️, 📋, ⇄ (not on top-level roots), 📂 Move (`MoveStatementDialog`, `excluded` = the node's own branch), 🗑️ (`DeleteNodeDialog`, `NodeToDelete`: says what goes with it)
- **Outline rendering** (`ContentOutline`): each node's line is one memoized component (`OutlineRowLine`, compared by `rowEqual`: the row's fields, level, connectors, state) with one stable `RowActions` object for every row (it reads the latest handlers through a ref); only the row being edited gets its field; the connectors are memoized on the visible levels; the root chips' counts on `rows`. Typing in a row, or opening one, re-renders no other row: `__tests__/outlineRenders.test.ts` (happy-dom, a 200-row outline; it counts row renders and fails against the previous version, which re-rendered all 200 rows on every keystroke)
- **Tree connectors** (`lib/treeGuides.ts` `treeGuides(levels)`, pure, tested in `__tests__/treeGuides.test.ts`): from the levels of the visible lines (collapsed branches left out, the new line and the bulk importer included) each line gets │ through-lines for ancestors that continue below, a ├ (`tee`) or └ (`last`, rounded) elbow into its bullet, and a stem from its own bullet when its children show. `ContentOutline` `OutlineLine` draws them as 1.5 px `border-amber-300/70` (dark: `border-stone-600/40`) strokes, column k at `k * STEP + 7`; verticals span the full row height and elbows meet the row at 50% (the bullet is centred on wrapped text), so wrapped rows leave no gaps
- **Deck draft** (`lib/draft.ts`, `components/DeckDraft.tsx`): ops `species`, `add { tempId, parentId, afterId, type, content }`, `addMany`, `edit`, `remove`, `move`, `indent`, `toggle`, applied with `contentTree` to `editor.rows` (the canvas tree and the root lists are derived). `confirmAdd` / `confirmMany` give real ids and retarget later ops; `settleOp`, `dropOp` (rollback), `rebaseOps`. Actions: `addNode`, `addStatement`, `addStatements`, `editNode`, `removeNode`, `moveNode`, `indentNode`, `toggleType` (toasts "Converted to Root / Statement"), `isPending`, `resolveId`. Tests: `__tests__/draft.test.ts`, `altShortcut.test.ts`
- **Bulk preview**: `BulkStatementImporter` rows have ✏️ (or double-click) to edit in place and 🗑️ to discard, plus "Restore N discarded"; `lib/bulkStatements.ts` `reviewBulkStatements(raw, existing, edits)`
